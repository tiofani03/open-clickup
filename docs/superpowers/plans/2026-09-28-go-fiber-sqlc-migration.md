# Go Fiber + sqlc Backend Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate Open ClickUp backend completely to Go using Fiber framework and sqlc for PostgreSQL, while preserving the Vite + React 19 SPA frontend, with standalone database migrations and a Go seeder runnable on any VPS or laptop.

**Architecture:** A standalone Go backend (`server-go/`) running Go Fiber on port 8080 (dev) and 3000 (prod), using `sqlc` for compile-time type-safe PostgreSQL queries and `pgx` driver. Realtime events are handled via Go channels and Fiber SSE streaming. The Vite frontend continues to communicate seamlessly via `/api` and `/uploads` proxies. A multi-stage Dockerfile builds both the Vite SPA and Go binary into a single, minimal Alpine/Scratch image (~25MB).

**Tech Stack:** Go 1.24, Go Fiber v2, sqlc v1.31, PostgreSQL 16 (`pgx/v5`), `golang.org/x/crypto/scrypt`, Vite 8, React 19.

---

## Global Constraints

- **Zero Breaking Schema Changes**: Must preserve existing PostgreSQL schema and data structures.
- **Port Compatibility**: In production, the single container listens on port 3000, serving the Vite SPA static files and routing `/api/*` and `/api/stream`.
- **Standalone Migrations & Seed**: Must include clean SQL migration files and a runnable Go seeder (`go run cmd/seed/main.go`) that creates demo data without requiring Node or Prisma.
- **Type Safety**: Use `sqlc` to generate Go models and database access methods from SQL queries.
- **SSE Realtime**: `/api/stream` must implement SSE using Go channels to broadcast hierarchy and task events to all active client tabs.
